# 机制诊断设计 v2（开发诊断，非确认性；按 Codex mech-design-v1-review D1–D5 修订）

## 问题
跨块 7 位数答案上，矩类打分器出错的那一步，携带正确数字的块（目标块）是否被选中；若未选中，是打分器排序遗漏（相对精确质量 oracle），还是在该状态下目标块的真实质量本来就不高。允许多种机制并存，不强迫二选一。

## 样本（D1）
现成的 34 个跨块提示（force_probe_16k，标签筛选，种子 1000–1059 候选）+ 29 个不跨块提示（shift_16k 中
straddle_orig = False，种子 1000–1019），共 63 个，称为"对照组"，不声称一一匹配；按任务分开描述。全部样本都纳入
描述，自由生成成败只作探索分层。冻结每个提示的 prompt/token 哈希。

## 标准答案续写与逐步对齐（D2）
提示已以答案前缀结尾；续写 = 模型实际格式下的 " " + 7 位数字 + "."（由分词确认），只喂续写。先验证
tokenize(prompt + 续写) 以 prompt 的 token IDs 为前缀；记录续写 token IDs、每个数字对应的续写步和 prompt 中该数字的
token 位置（来源 span）。第 j 步先记录对 y_j 的 log-prob、与最强非 y_j token 的差值、argmax，然后才喂入 y_j。
自由生成分三类记录：首次 token 偏离位置；可对齐回答中的首个错误数字；格式偏离 / 提前 EOS / 无数字。只有当自由
生成前缀与标准前缀真正一致时，才把对应的逐 token 喂入步称为"同状态诊断"。

## 两类诊断（D3）
A 共享状态：在稠密逐 token 喂入的每一层、每一步，用同一 Q/K、同一子空间 W、同一候选集合，计算各打分器
（cobs、nf_pt1、quest）的选择以及精确块 log-partition 排名；不改写参考缓存。标注 state_origin = dense_TF。
B 各自轨迹：每种方法在自己的逐 token 喂入（和自由生成）状态里，同时记录自身排名与精确 log-partition 排名；
state_origin = arm_TF / arm_FR。每个臂都从同一份冻结的预填充状态恢复（缓存裁回 L−1）。
目标块 = 当前要预测的数字在 prompt 中所在的块（按 token span）；另记头块、尾块、键词块，重合时报告重合；
标记固定区 / 候选区 / 不可选边缘。不跨块样本的头块 = 尾块，+ftail 在那里不是独立因素。

## 记录与结果类别（D4）
每步、每层，对目标块记录：实际 k、精确 log-partition 名次（并列取平均名次）、与第 k 名的差、打分器名次、
是否被选中、（+ftail）是否发生替换及被替换块；块内分数的精确均值 / 方差与投影（W）方差，以及
peak − log-partition（集中程度）。结果类别：当前状态下的排序遗漏（精确 top-k 内但未选中）；已选中仍失败；
质量 oracle 也遗漏（精确名次在 top-k 外）；轨迹间不一致；混合 / 信息不足。不从质量排名推断因果重要性。
删除 v1 中"两种机制都不预测边界前出错"的说法。

## 汇总（D5）
同时给出每层的不加权选中比例与加权比例（权重 = 稠密逐 token 喂入同一步、同一层、同一头对目标数字 token 的
注意力），写明分子、分母、阈值与汇总顺序；近零权重单独计数，不默认为 0 或 1；逐提示表格完整保留。
加权平均只作描述，不替代干预效应。

## 执行
先在 4 个预先指定的提示（每任务各 1 个跨块、1 个不跨块）上做实现检查：数字定位、无状态污染（首个相同前缀步
各臂一致的检查点）、swap、预算不变量、字段完整性；用实际耗时估计全量成本，再跑 63 个。排在 F3 与第一阶段之后，
低占用模式。
