## A. 方法层面的增益——满足任一“无条件”项即“有方法价值”
- **A1 等内存优势**（无条件）：rep2 上 cobs+g2f − cobs16 的 95% 下限 > 0。
- **A5 最强摘要族上的 TWIN-GRID**（无条件）：quest16+g2f − quest8 的 95% 下限 > 0（等内存：每 token 32 float；B = 8 与 16 都以 U = 32 匹配布局）。
  另报 quest16+g2f − quest16（只作描述）。
- **A4 内存效率**（无条件）：EM 打分器（B32，每 token 12 float，为 quest16 的 75%）em − quest16 的 95% 下限 > −0.02，记为“内存效率收益”。
- **A2 固定粒度下的增益**（条件性）：R5 复现，**并且**在目标 GPU 上用真实块稀疏 decode kernel 实测，相同读取预算下 B16 比 B32（含 TWIN-GRID 开销）慢至少 10%。
  论证或引用都不算前提证据；没有实测记为“条件性增益（前提未证）”，不算价值。
  反面证据（已核对原文）：Quest 论文 §3.5 用每页 16 个 KV（“Assuming that we use 16 KV pairs per page”），vLLM 的默认 KV 块长为 16
  （`DEFAULT_BLOCK_SIZE: ClassVar[int] = 16`），所以“粒度必须是 32”在常见系统中缺乏依据。
- **A3 与最强基线持平**（条件性）：某个“摘要 + TWIN-GRID”组合在等内存下不劣于最强的 Quest 配置（95% 下限 > −0.02）。“不劣”本身不是价值，
  必须同时实测证实成本优势（同 A2 的实测形式），否则不算。

## B. 性能优化（速度、显存、吞吐）
没有真实 block-sparse kernel，**没有速度证据**，记为“未知”，不计为价值。

## C. 认识层面的价值（用户 2026-10-17 确认计入）
- **C1**：摘要类型主导、块长三效应在 rep2 上复现——**R1 复现、R2 复现、R3 至少部分复现、R4 等价，四条同时满足**（R1 是三效应解释的核心证据，
  R1 不复现则三效应的解释不成立；审查方批次 13 收紧）。
- **C2**：增益律在固定块长下校准成立——**R6 的合计 κ“相符”**（预先登记的主读数一直是合计 κ；分打分器的 κ 只作描述，不用于判定，以免事后挑选）。
  证据力度说明（2026-10-18，勘误 E1，不改判定规则）：两折交叉拟合不能消除合计 κ 中 Δ 与预测的共享噪声，所以 C2 即使“相符”，也只是同一样本上的
  描述性校准，作为认识层面证据的力度低于独立预测验证；报告中如实写明。
- 新颖性如实写明：box 摘要有效是 Quest 已有的结论，更细的块更好也属常识方向；本项目增加的是同一协议下的定量分解（切分惩罚 G 的度量、三效应的分离、增益律）。

## 判定与后续
- A 中任一无条件项成立 → 有方法价值：写计划 v2（三层），只围绕该价值设计对比；以 v2 取代 v1.4 是正当的（尚无任何集群数据）。
- A 全部不成立 → 写明“按用户口径，本项目提出的方法（TWIN-GRID、EM 打分器）没有可证实的性能、收益或增益价值”。

## 判定结果（2026-10-19；rep2 全门控通过，7d669b4；Codex 独立复核通过）
按上文口径逐项判定（规则未改）：
- A1 不成立（cobs+g2f − cobs16 = −0.065 [−0.096, −0.037]）；A4 不成立（−0.043 [−0.059, −0.027]，下界 < −0.02）；A5 不成立（quest16+g2f − quest8 = −0.024 [−0.035, −0.014]）。
- A2：R5 复现，但没有真实 kernel 实测，记为“条件性增益（前提未证）”，不算价值。A3：quest16+g2f 对最强的 quest8 下界为 −0.035 < −0.02，不满足“不劣”，也没有成本实测。
- B：未知（不等于零收益）。
- C1 成立（R1、R2 复现，R3 完全复现，R4 等价）；C2 相符（合计 κ 1.06 [0.68, 1.60]），证据强度按 E1 降为同样本的描述性校准。
结论：按用户口径，本项目提出的方法（TWIN-GRID、EM 打分器）在所测配置（Qwen2.5-1.5B、16k、7 个 RULER 任务、预算 512/1024）下没有可证实的性能、收益或增益价值；
认识层面成立。按“C 成立”的后续条款，已写认识层面的三层计划草案 docs/PLAN_V2_COGNITIVE_ZH.md，开头写明新增认识与已有结论的边界，供用户判断是否值得使用集群算力。
