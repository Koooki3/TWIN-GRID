## 0. 先回答：这批算力能换来什么新认识，边界在哪里

**一句话**：免训练块稀疏注意力在选块时，有限的摘要内存该花在哪里——换更强的摘要类型、把块切细，还是加一套错位网格？
本机 1.5B 给出的答案是“摘要类型 ≫ 细分 > 错位网格”，并且“块边界切分对不同摘要的伤害可以量化（G）”。v2 检验这个答案在更大、不同族的模型上是否仍成立，
以及 G 能否在独立样本上预测布局修复的收益。

**这对谁有用**：设计 Quest 类页面选择、NSA 类小选择块等免训练选块方法的人。v2 若成立，可以给出三条可操作、可证伪的结论：
1. 等内存时，把预算花在更细的块上，而不是错位双网格（H1、H2）；
2. 选块前先看摘要类型的切分惩罚 G：G 小（box 类）时，布局改进几乎无收益；G 大（矩类）时才值得考虑（H3）；
3. 若 H4 成立：只用单网格臂测得的 G 与运行前已知的跨界比例 π，就能预估布局修复的收益，不必为每种布局都跑一遍（探索性）。
若不成立，同样有用：说明 1.5B 上的分解不能推广，实践中不应据此取舍。

**本机已有结论**（Qwen2.5-1.5B、16k、7 个有单元的 RULER 任务、预算 512，R7 另测 1024；rep2 新样本；Codex 独立复核通过，7d669b4）
1. 方法价值不成立：所测配置下，TWIN-GRID 与 EM 没有可证实的性能、内存或增益收益（速度未知，不等于零）。
2. 认识层面（描述性复现）：
   - 等内存下细网格胜过错位双网格：矩类 cobs16 − cobs+g2f = +0.065 [+0.037, +0.096]；box 类 quest8 − quest16+g2f = +0.024 [+0.014, +0.035]；
   - 摘要类型差距大：quest32 − mean+g2f = +0.224；
   - 切分惩罚 G = acc(in0) − acc(repair)：G_mean .302 > G_cobs .231 > G_quest .031；
   - 增益律合计 κ 相符，但只是同样本的描述性校准（勘误 E1）。

**v2 共用主问题（三层都能测，判定定义不随层改变）**
- **Q1**：在 Llama-3.1-8B-Instruct / 16k / 预算 1024 的主格上，在**有单元的 9 个任务**（§3.2 名单）中，等内存的细网格是否仍胜过错位双网格——矩类（H1）与 box 类（H2）？
- **Q2**：同一主格上，切分惩罚是否仍是 cobs 大于 quest（H3）？这是 8B 内部的排序，**不是**跨模型比较：rep2 是 Qwen 1.5B / 预算 512，模型与预算都不同；
  H3 不拒绝不能推出“G 变小”，v2 不对跨模型衰减下结论。
- **Q3（探索性，不进入 Holm）**：在**独立的校准样本**上，只用单网格臂测得的 G，按固定 R = 1 的结构律，能否在主样本上预测 TWIN-GRID 的增益，并且比不含格子信息的简单基线更准（H4）？

**不在共用主问题里**（只在能测的层作辅助或描述，或留到以后）：mean 的完整 G 排序与 quest32 − mean+g2f（层 2 起）；跨模型或跨预算的 G 变化；13 任务的官方总分；其它长度与预算。

**与已有结论的边界**：box（min/max）摘要有效是 Quest 的结论；“块越细越好”属常识方向；错开半块的布局在 NSA 压缩分支中已有（l = 32、d = 16，端到端训练）。
v2 增加的是：在另一模型族与更大模型上，按事先定义的估计量重测等内存的网格比较与切分惩罚；以及检验 G 是否真有独立于 TWIN-GRID 臂本身的预测作用。
负结果（双网格在等内存下不如细分）只针对免训练选择与所测两类摘要，不推出 NSA 的设计不对。用户已据此决定使用集群算力（2026-10-19）。

## 3. 协议

### 3.1 官方 harness 与模型身份
- RULER v1 旧 scripts（commit `c3f5e3b`），prepare 与 evaluate 不改。官方 prepare 用固定种子，每任务生成 500 条并冻结（文件哈希入清单）。
- **强模型身份**：每个 manifest 记录 HF repo、revision 与全部权重文件的内容 sha256，缺了即拒绝汇总，不得事后补记。
- 适配验收同 v1.4 §3.2（含数值平局规则）。

### 3.2 数据、分析集合与权重（预测前冻结）
- **主样本**：冻结文件行 0..99；**校准样本**：行 100..199。
  - 两者不相交：行号不同，input 哈希无重合。
  - 但两批出自同一次 prepare，haystack 取自同一批源文本（如 Paul Graham essays），所以 input 哈希不同只是必要的身份检查，不能自动证明统计独立。这一点如实写明。
- **单元长度文件**：cluster/unit_lengths.py v3，用该模型自己的 tokenizer，B = 32 类别，覆盖**行 0..199（n = 200）**；在任何预测之前冻结，sha256 填入 §8。
- **有单元任务 S_unit**（机械规则：冻结代码 `NO_UNIT = (cwe, fwe, qa_1, qa_2)` 之外的任务）共 9 个：
  niah_single_1、niah_single_2、niah_single_3、niah_multikey_1、niah_multikey_2、niah_multikey_3、niah_multivalue、niah_multiquery、vt。
  - 其中 niah_single_3、niah_multikey_3 是 UUID 任务：有单元，但按 ℓ ≤ B/2 + 1 判为不可覆盖；它们在 S_unit 内。
  - “可覆盖子集”只作描述，不作任何 H 的分析集合。
- **权重**：H1–H3 都按答案单元加权，把 S_unit 内全部答案单元合在一起，与 rep2 的估计量相同；任务等权的版本只作描述。
- 4 个无单元任务以及 13 任务的官方分数只作描述；任何 H 都不声称对 13 任务总体成立。

### 3.3 Holm 族（α = 0.05，恰好三项，单侧方向事先写定；只在主样本、S_unit 上判定）
- **H1**：acc(cobs16) − acc(cobs+g2f) > 0，S_unit 内全部答案单元（所有类别）。
- **H2**：acc(quest8) − acc(quest16+g2f) > 0，同上。
- **H3**：G_cobs − G_quest32 > 0。
  - 定义：G_a = acc_a(in0) − acc_a(repair)，类别来自冻结的 32 网格单元文件，S_unit 内合并；fixed 与 out 类不进入 G。
  - 可估计条件（只看单元文件，与结果无关）：主样本 S_unit 内 in0 与 repair 单元各至少 50 个；否则 H3 记“不可估计”。

**检验（V5）**
- **交换单位**：样本。对每个样本，以 1/2 概率把两臂的**全部**答案结果整体互换；类别标签与样本身份保留，不对答案单元单独翻转。H3 每次重算两臂的两个类别率及其差。
- **零假设**：每个样本内，两臂结果的联合分布对臂标签互换不变（尖锐的可交换零假设）。这比“均值差为 0”更强，报告中照此表述。
- **参数**：
  - 置换次数 100000，种子 20261019 + k（k = 1, 2, 3 对应 H1–H3）；
  - 单侧 p = (#{T* ≥ T} + 1)/(100000 + 1)，平局计为极端；
  - 区间用按任务分层、整样本重采样的 percentile bootstrap 95%，4000 次，种子 20261019，同一样本的所有臂与单元一起抽。区间只作单项描述，判定用 Holm 调整后的 p。
- **H3 的空类别**：置换只互换臂，不改变类别计数，主样本的门槛（各 ≥ 50）保证置换统计量总可计算。
  bootstrap 区间则可能在某次抽取中缺 in0 或 repair：该次抽取对 H3 区间记为无效，按 §3.4 的 1% 规则传播，只影响描述性区间，不影响由置换 p 与 Holm 作出的判定。
  H1/H2 包含所有类别，不受空类别影响。
- **Holm**：三项固定。某项不完整或不可估计时，记“未判定”，按 p = 1 计入（不拒绝），族大小仍为 3，不临时缩小。
- **判定写法**：拒绝 → “在 8B / 16k / 预算 1024 / S_unit 上成立”；不拒绝 → “未在该主格上证实”。不写“不存在”，也不推出 G 变小。

### 3.4 H4：独立样本上的预测评估（探索性，不进入 Holm，不作确证；V1–V2）
- **共用主读数只用 cobs**（三层相同）。mean 的读数是层 2 起的辅助读数，单独报告，不与 cobs 合并成主读数。
- **格子** c：S_unit 中满足以下条件的任务——校准样本中 in0 与 repair 单元各至少 20 个（只看单元文件）。其余任务列为“不可估计”，不静默剔除。
- **增益分解**（写全）：Δ_c = Σ_class π_c,class · (t_c,class − b_c,class)，class ∈ {in0, repair, out, fixed}；t 为 cobs+g2f，b 为 cobs。主样本上逐项报告四个类别的贡献。
- **结构律预测**（事先固定 R_repair = 1，in0、out、fixed 三项为 0）：pred_c = π_c^main · G_c^calib。
  - π_c^main 是主样本的 repair 单元占比，来自单元文件，运行前就已知；G_c^calib = b_in0 − b_repair，只用校准样本的 cobs 单网格臂。
  - 这里 R 不拟合，所以不出现 π·G·R̂ = π·(t_r − b_r) 中 G 被代数消去的问题。
  - 拟合 R 的版本（π·G·R̂_calib = π·(t_r − b_r)_calib）明确称为“校准集修复增益的样本外迁移”，只作辅助参照，不称为增益律验证。
- **基线**：
  - B0 零预测；
  - B1 常数预测：校准样本中各格合并的 Δ，按单元加权，对每格取同一值，即不含格子信息；
  - B2（参照）：校准样本上直接测得的 Δ_c。B2 用到双网格臂，属于迁移，不是结构律。
- **误差与读数**（权重 w_c = 主样本中格 c 的答案单元数）：
  - E_X = Σ_{c∈C} w_c |Δ_c^main − pred_c^X| / Σ_{c∈C} w_c；
  - 主读数为 E_law − E_B1，附 95% 区间（重采样规则见下）。
  - **相对标签**：上界 < 0 → “在 C 上，结构律的加权平均绝对误差小于常数预测”；下界 > 0 → “大于常数预测”；否则“不确定”。
    相对标签与绝对精度标签分开报告：“优于常数预测”不等于“足够准确”。
  - **绝对精度标签**（R1-b）：
    - E_law 的 95% 上界 ≤ 0.03 → “在预定可估计任务集合 C 上，答案单元加权的平均绝对预测误差的 95% 上界不超过 3 个百分点”。这不保证每个任务的残差都 ≤ 3pp。
    - 下界 > 0.03 → “加权平均绝对误差明确超过 3pp”。
    - 其余情况 → “未证实达到预定的加权平均 3pp 精度”。这可能只是区间太宽，不作否定。
    - 3pp 是事先选定的探索性规划容差（约为 rep2 单格增益量级 0.05–0.10 的一半），不是已经证明的普遍阈值，也不是对单格误差的控制。
  - 同时报告 E_law − E_B2、逐格残差表，以及合计 κ = ΣΔ/Σpred（只作辅助：它会掩盖单格误差）。
- **格子集合 C 的状态**（只由单元文件决定，与结果和重采样无关）：
  - |C| = 0 → H4 整项“不可估计”；
  - |C| = 1 → 只报告该格的残差与绝对精度标签，相对标签记“不适用”（一格时 B1 与 B2 重合，不能检验跨格的预测能力）；
  - |C| ≥ 2 → 照上文。
  - 报告中始终列出 C、被排除的任务及原因，以及 C 覆盖的任务数与 S_unit 答案单元占比。
- **重采样规则**（R1-a；目标为“几何随样本一起重采样”的无条件目标）：
  - 每次 bootstrap 抽取：主样本与校准样本各自独立地按任务、整样本有放回重采样，同一批内所有臂共用同一组配对索引；
  - 在抽到的样本上重算 π_c^main、w_c、Δ_c^main，以及 G_c^calib、B1 的校准合并 Δ、B2 的 Δ_c^calib；
  - C 固定不变，不随抽样或结果改变；4000 次，种子 20261019。
  - **无效抽取**：若某次抽取中 C 里有任何一格在校准重采样里缺 in0 或 repair，该次抽取对 H4 的全部读数（E_law、E_B1、E_B2 及差值）整体记为无效。不丢格、不重新归一化权重，也不补抽凑足 4000 次。
  - **传播**：
    - 无效比例 f ≤ 1% → 用有效抽取计算 percentile 区间，并报告 f，注明该区间以“抽取有效”为条件；
    - f > 1% → 相关区间与标签记“不可判定”，只报告点估计与诊断（各格缺类别的次数）。
    - 1% 现在写定，不看 8B 结果调整。
  - 点估计用原样本计算；原样本中 C 的各格按定义都有 in0 与 repair，不会无效。
- **辅助 κ 的分母**：
  - 点估计 |Σpred| < 0.005 → κ 记“不可估计”；
  - bootstrap 中 |Σpred| < 0.005，或 Σpred 与原样本异号的抽取，对 κ 记为无效，按同样的 1% 规则传播；
  - 不用 nanpercentile 静默跳过。κ 的状态不影响主读数。
- **锁定**：预测公式、阈值与纳入规则在任何主样本输出解盲之前锁定；校准样本与主样本可以按资源调度，但不能看到主样本结果后再调。
  G_c^calib 为 0 或为负时照常预测，pred 本身不做除法。

### 3.5 功效（规划用近似，不是算力承诺；theory/power_v2.py，results/power_v2.log；V6）
- 直接从 rep2 的真实预测按每任务 100 样本重采样估计标准误（4000 次，种子 20261019），不再用 √(80/100) 缩放；判定口径为单侧、Holm 最严一步 α = 0.05/3，用正态近似。
- 这些是 1.5B / 预算 512 的标准误。rep2 的点估计也不是 8B 的预期效应，所以列出敏感性情景：
  - 效应 ×1 / ×0.5 / ×0.25；方差 ×1 / ×1.5；
  - H1、H2 另加 UUID 两任务的稀释情景（零均值、方差取单单元任务的经验值，这是假设）。
- 最小可检出效应（功效 0.8，按比例计）：
  - H1 0.039（加 UUID 后 0.036）；
  - H2 0.014；
  - H3 0.085。
- 功效：
  - 效应与 rep2 相同时三项都 ≥ 0.94；
  - 效应减半时 H1 0.44–0.64、H2 0.39–0.66、H3 0.77–0.91；
  - 效应为 1/4 时都 ≤ 0.35。
  - 即：若 8B 的效应只有 1.5B 的一半或更小，H1 与 H2 很可能检不出。这是用户决定算力时需要知道的风险。不显著不作“效应不存在”或“G 变小”的结论，也不追加样本。
- H3 的功效**没有模拟 UUID 任务带来的类别变化**（8B tokenizer 下 UUID 任务的 in0/repair 构成未知），只是按 rep2 的 7 个任务估计的。
- 这是经验分布上的正态规划近似，不是对实际置换检验与 Holm 的功效模拟；单侧 α/3 是最严一步的保守口径，不代表 Holm 的整体功效。
- 可追溯：输入与代码哈希见 results/power_v2_inputs_sha256.txt；Codex 独立重算吻合（v2-r1-power-verification.json）。
- H4 是探索性的，不作功效承诺。

### 3.6 停止规则
- 适配验收不通过，或显存探测不过，即停。
- 中断按同一命令续跑；不删样本，不替补。主格不完整的相关项记“无法判定（不完整）”。
- 看到主格结果后，不追加臂或样本，不更换主比较或分析集合；辅助格不以主格结果为条件启动或取消。
