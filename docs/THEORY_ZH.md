## 1. 框架：块稀疏 decode 的两个误差源

固定读取预算下，decode 只读入被选中的块。选错有两个互不相同的来源：

- **(i) 摘要不能确定块的质量。** 块摘要 S 只约束了块内分数 {s_i} 的可行集，因此块对数质量 A = log Σ e^{s_i} 只能确定到一个区间。
  §5 给出三类摘要的区间（P1–P3）；EM 打分器取 P2 的上端。这一来源决定“存什么”。
- **(ii) 划分把单元切开。** 单元被网格边界切开时，没有任何一个块完整地包含它，无论摘要多精确。这一来源决定“在哪里切”。

**TWIN-GRID 只针对 (ii)**：同时提供两套错开 h 的网格作候选，在与单网格完全相同的候选 token 预算内贪心填充（g2_fill_v1）。
它的效果由 §4 的增益律刻画：L1 给出适用范围，L3 说明它没有表示能力上的优势，L4 说明收益来自选择规则，§3 的 F 模型说明 G 为何随摘要类型变化。

## 2. 划分

**L1（k 网格覆盖；已证）。** k 套块长 B、依次错开 B/k 的网格（k | B）：任何长度 ℓ ≤ (k−1)B/k + 1 的连续段都完整落在某套网格的一个块内，且该界是紧的。
证明：所有网格的边界并集间隔为 B/k；段跨越的边界位于 ℓ−1 个连续整数中，至多含 ⌈(ℓ−1)/(B/k)⌉ ≤ k−1 个并集边界，故至少有一套网格无边界落入；
(k−1)B/k + 1 个连续整数可以恰好各含每套网格的一个边界。k = 2 时为 ℓ ≤ h + 1（B = 32 时为 17）。
核验：theory/verify_cover.py、verify_kgrid.py（B ∈ {4,…,64} 穷举，rc 0）。

**适用范围。** L1 是几何覆盖。可被利用还要求覆盖块在候选区内：落在共同内部区 [B+h, C−h) 的单元才一定可修复。
据此把单元分为 fixed / in0 / repair / out 四类（§0）。L1 只是充分条件：ℓ > h+1 的单元也可能恰好落在网格 1 的一个块内，被归为 repair（例如 Llama-3.1 下 UUID 任务的部分单元）。
因此集群分析一律按逐单元类别处理，“任务是否可覆盖”只用于登记的任务子集检验。

**L2（细网格；已证）。** 块长 h 的单网格会切开每一种长度 ≥ 2 的段中的某些位置；长度 ≤ h + 1 的段至多跨两个块。

**L3（可行集包含；已证，Codex G2）。** 设细网格（块长 B/k）与每套粗网格的边界对齐，常驻区相同，粗候选块内的每个细块都可选，且预算按去重后的 token 计。
则每个粗块是 k 个细块的并，任意多套错开粗网格可达的 token 集合，细网格都能以不更多的读取达到。
推论：对只依赖“读到哪些 token”的理想目标，错开网格**没有表示能力上的优势**；实际差异只能来自摘要、排序和预算内的选择规则。

**L4（单次选择 vs 联合选择；条件命题，审查方 T3）。** 设某单元在细网格上被切成落在块 b₁、b₂ 的两段，而在双网格上被块 b* 完整包含。
记 E_b 为块 b 的分数进入 top-k 阈值的事件。细网格要读全该单元需要 E_{b₁} ∩ E_{b₂}，双网格只需 E_{b*}。
由 P(E_{b₁} ∩ E_{b₂}) ≤ min(P(E_{b₁}), P(E_{b₂}))：只要 P(E_{b*}) ≥ min(P(E_{b₁}), P(E_{b₂}))，就有 P_twin ≥ P_fine。
在两层模型（§3）下，若 f < ½ + 1/Δ（二阶分数对 f 单调增），入选概率随分数单调，且较小碎片的占比 2m_min/B ≤ ℓ/B，
则矩摘要对碎片的打分不高于整块，这个条件成立；对 box 摘要，碎片与整块分数接近，但仍需两段同时入选。
这是条件命题，真实的阈值、噪声和块间相关都可能破坏它，它的经验内容就是登记预测 P-grid：等摘要内存（cobs@16 vs cobs+g2f@32），
在被 16 网格切开的单元上，预测 twin ≥ fine。审查方的玩具模拟显示 F、R 两种机制都预测这一方向，所以 **P-grid 检验的是选择规则，不区分机制**。
跨块长比较须按 G3 匹配常驻区、候选区、候选读取数和去重后总读取：实现上引入布局单位 U（`--layout-unit`），sink、尾窗起点与候选 token 预算都按 U 计，
候选块仍按 B 切；B = 16、U = 32 时与 B = 32 的上述各项逐一相同（theory/check_g3_layout.py），U = B 时与原实现逐位一致。

**g2_fill_v1 的预算。** 双网格候选在与单网格相同的候选 token 数内按分数贪心选取（以半块计覆盖），每次调用断言读取预算（--strict-budget）。
摘要量约为单网格的 2 倍（不是等内存方法）；“每次选择的候选读取预算不增加”是已证的实现性质（Codex g2-fill-budget-proof），不是零额外读取。

## 3. 摘要对划分的敏感性（F 模型；已证于模型，部分符合）

两层块：B 个 token，其中 m 个（单元）的 logit 为 μ + Δ，其余为 μ；f = m/B，t = e^Δ − 1。
- F1（精确质量）A − log B − μ = log(1 + f t)。
- F2（二阶累积量，未投影的 COBS 式）K − μ = fΔ + ½ f(1−f)Δ²。
- F3（最大值 / box）块最大值对任意 m ≥ 1 都是 μ + Δ；逐通道 box 界只通过单元 token 的逐通道包络依赖 m。

切开后（Q/K 固定，0 < f₁ ≤ f）：δA = log((1 + f t)/(1 + f₁ t)) ∈ [0, log(f/f₁)]；δK = (f − f₁)[Δ + ½(1 − f − f₁)Δ²]（精确）；标量最大值不变。
**δK > δA 不是一般定理**（反例 B = 32、m = 2 → 1、Δ = log 33：δA ≈ 0.405 > δK ≈ 0.282）；在部分参数区间内二阶近似把对 f 的对数依赖放大成陡得多的依赖
（例 m = 7 → 4、Δ = 6：δA = 0.55，δK = 1.67 nats；theory/verify_fraction.py）。精确质量 oracle 的排序也会因切开而翻转（Codex 反例），排序保持需要显式的间隔条件。

**可检验的推论（G 的顺序）**：跨界惩罚 G 的大小由摘要类型决定，矩摘要 > 归一化变体 > box。这条与 R 无关，可独立证伪。

**读取需求（R 机制；假设）**：复制 value 时，每个 decode 步需要读到下一个源 token 所在的块；内容打分器借助 query 与 key 短语的相似度找到它。
若切点把 value 的末尾几位留在不含 key 短语的块里，这个块必须靠自身分数入选。F 对“哪一侧碎片含 key”是对称的，R 不是。
本机确认数据上的切点位置统计（§6 E5，事后）与 R 相容，也与非均匀 F 相容；F、R 不互斥，本文不作“哪个机制胜出”的结论。

## 4. 增益律

对打分器 s、任务 t（按单元计）：

  Δ = π_rep · G · R + π_in0 · (a′_in0 − a_in0) + π_out · (a′_out − a_out)

其中 π_c 为类别 c 的单元占比（π = π_rep），fixed 单元两臂都读，不贡献差异。**这是由 R 的定义直接得到的恒等式，本身不可证伪。** 理论给出的可检验内容只有三条：

1. **G 的顺序**由摘要类型决定：矩 > 归一化 > box（§3 F2/F3）；
2. **范围内 R ≈ 1**，且段内项 a′_in0 − a_in0 ≈ 0（L1 + g2_fill_v1 的等预算；段内项可能因候选数翻倍而略为负）；
3. **范围外 R → 0**（out 类单元，两套网格都无法完整包含）。

于是预测 **Δ̂ = π · Ĝ**：π 由 tokenizer 在运行前精确给出，Ĝ 只用基线臂估计。这把“有没有增益”升级为“增益大小是否吻合”：
Quest 的近零增益（G 小）、UUID 与无单元任务的近零增益（π 或 R 为 0）都是这条规律的预测，而不是需要另行解释的失败。

**集群上的检验（P-gain，登记的描述性分析，cluster/gain_law.py）**：
- 稳健性措施：Ĝ 与 Δ 都含基线的 a_repair，因此 Ĝ 用行号奇偶两折交叉拟合（一折估计、另一折预测、再交换）。
  审查方模拟（checks/sim_kappa_bias.py）显示，在真值 κ = 1 时，现行实现的均值/中位数为 1.003/0.999（G 偏小情景 1.039/1.000），不做交叉拟合也约为 1.00；
- 主读数是合计校准比 κ = Σ_格 Δ / Σ_格 π·Ĝ_cf（格 = 打分器 × 有单元的任务；按格合计再相除，相对误差远小于逐格比值），增益律预测 κ ≈ 1；
- 辅助读数：过原点的校准斜率（受 Ĝ 噪声影响会衰减偏向 0）、按类别合计的 R̂_repair（≈ 1）与 R̂_out（≈ 0）、段内项；
- 区间：任务内、以样本为单位的分层 bootstrap（同一样本的多个单元不独立），每个重样本内部重做交叉拟合；
- 自检：theory/check_gain_law.py（规律成立时 κ 区间覆盖 1；R = 0.5 时 κ ≈ 0.5、区间排除 1）。

## 5. 摘要该存什么（误差源 (i)；经典结果的新用途）

- **P1（均值 + 方差；经典）**：m + φ_n(−s) ≤ A − log 1 ≤ m + φ_n(s)，φ_n(t) = log(e^{t√(n−1)} + (n−1)e^{−t/√(n−1)})，紧。
  宽度 Δ_n(s) = s(n−2)/√(n−1) − log(n−1) + o(1)：只看 (m, s, n) 的估计在某些输入上至少差 Δ_n/2。这是二阶（COBS 式）摘要的最坏情形不可辨识性。
- **P2（均值 + 区间；经典界的新用途）**：s_i ∈ [a, b]、均值 μ 精确时，log n + μ ≤ A ≤ log n + log(((b−μ)e^a + (μ−a)e^b)/(b−a))（Jensen | Edmundson–Madansky）。
  EM 上端 ≤ log n + b（Quest 的界），仅当 μ = b 时相等。有限 n 的精确上端为 Z_max = (n−r−1)e^a + r e^b + e^{a+θ(b−a)}（t = n(μ−a)/(b−a)，r = ⌊t⌋，θ = t − r；theory/verify_em_finite.py）。
  打分器 em 取 EM 上端（不用 Z_max）。摘要量为 3 个向量 / 32 token，约为 Quest-16 的 75%。
- **P3（精确异常值 + 主体；已证）**：精确存储 m 个最大范数 token，对其余 token 用其自身的均值与 box 套用 P2，再以 log-sum-exp 合并。在所检索的文献中未见此组合（候选贡献，不是新定理）。

em vs Quest 属于误差源 (i)，在集群计划中只作描述（不进 Holm 族）。

“在右”时 value 本身被切开：

| 打分器 | m ≤ 3，较小碎片在左（切点靠近 key 开头，value 完整在右） | m ≤ 3，较小碎片在右（value 末尾 1–3 个 token 被切走） |

不对称集中在 m ≤ 3；m = 4–5 时两侧接近（COBS 式 13/23 vs 10/18）。两组碎片大小相同但内容不同，所以它**不能区分 R 与 F**：
它与 R 相容（value 末尾几位落在不含 key 的块里，须单独入选），也与 key token 和数字 token 的 Δ 不同的非均匀 F 相容；
它只排除“均匀 Δ、单元为 kv 段的两层 F”。另一条更干净的信息是：只切开 key 时 COBS 式仍失败 7/34 ≈ 0.21，高于段内本底（约 0.05），
支持单元应包含 key（与 P-kv 一致）。集群上登记为描述性读数 P-asym（“value 被切 vs 只有 key 被切”），不作为 R 的检验。

**E6 机制诊断（63 题，开发选定；描述性）**：在共享的 dense teacher-forced 状态上，POST 组的 exact definite-in、full-moment definite-in 与实际入选率都低于 IN 组。
IN − POST：exact +0.109，full-moment +0.168；实际入选 cobs +0.256，nf +0.207，quest +0.161。
首个自由生成分歧落在第一个 POST 数字上的比例很低（cobs 23 次中 4 次），对最简单形式的 R1 没有直接支持。
它作为“G 的来源”的描述性证据：矩摘要在跨界后对含单元块的排序下降最多。它不能分离切分的因果效应，也不确认单一机制。

**E7 适配验收（本机 1.5B）**：4 项顺序与缓存隔离检查全部一致（生成进入候选区）；相同输入对照 14/15 条输出一致。
严格判定 NOT ACCEPTED。不一致的 1 条（cwe 第 4 条）是第 3、4 个词互换，官方计分相同；诊断与 bf16 平局相符：
官方路径在首个分歧步 top-2 为 “ prosecution” / “ ch”，logit 18.75 / 18.5，差距 0.25 = 2 个 bf16 ulp（[16, 32) 区间 ulp 为 0.125），
适配器取第 2 名，输入 token 相同；分块 prefill 时恰好打平（results/accept_tie_cwe4.json、accept_diag_cwe4.out）。
平局规则是看到这条结果后增设的；按其 2% 上限，15 行的本机验收仍为 NOT ACCEPTED（results/accept_ties_local.log），规则只对冻结后的集群验收算预先规定。

## 7. 未解决问题

- **G 的机制来源**：E5 与 R 和非均匀 F 都相容，E6 支持矩摘要排序下降是一部分；区分二者可比较 key token 与数字 token 的 dense 质量（mech_full 已有 dense 权重，只需 CPU）。
  P-gain 的分打分器读数是集群上的第一次检验。
- **R ≈ 1 是否迁移到 Llama-3.1-8B**：8B 模型在跨界单元上的本底失败可能更低（G 更小），此时主比较的功效会下降（计划 §3.5）。这是预测，不是要回避的结果。
- **P-grid**：G3 匹配已实现（CPU 检查通过），等摘要内存对照尚未在 GPU 上运行（本机开发运行与集群层 2）。
