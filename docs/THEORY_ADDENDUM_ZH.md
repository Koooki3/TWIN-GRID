# TWIN-GRID 理论附录 A1：主要竞争方案——分隔符分块（2026-10-16）

> docs/THEORY_ZH.md 已随计划 v1.4 冻结，本附录不改动它，只补充审查方批次 5 要求的对照。记号同 THEORY §0。
> 状态：理论比较为**已证 / 论证**；实验对照只有本机开发运行（探索性质），集群上至多作为 v1.4 的描述性附录。

## 1. 为什么它是第一个要回答的对照

TWIN-GRID 针对的是误差源 (ii)：固定网格切开了检索单元。另一种直接的思路是按内容切块，让块边界落在分隔符（句号、换行等）上。
RULER 的 needle 本身就是完整句子（“One of the special magic numbers for {key} is: {value}.”），所以按句号切块天然能把整个 needle 放进一个块。
读者首先会问的是：既然内容分块能直接避免切开单元，为什么还需要两套错开的网格？

## 2. 两种方案的结构差异

| 方面 | 分隔符分块 | TWIN-GRID |
|---|---|---|
| 块边界 | 由内容决定（分隔符先验） | 与内容无关（两套固定网格，错开 B/2） |
| 块长 | 变长：句子过长时截断，过短时合并 | 固定为 B |
| 摘要数 | 随句子数变化，最坏情况与 token 数同阶（大量短句或截断） | 固定为单网格的 2 倍 |
| 选择 | 变长块的预算装箱（0-1 背包，贪心近似）；跨块比较质量必须补回 log(块长)（THEORY §5 P2） | 等长块；g2_fill_v1 按半块单元精确填满预算（已证） |
| 覆盖保证 | 单元完整落在一个句子内且句长 ≤ 块长上限时才成立 | L1：任意 ℓ ≤ B/2 + 1 的连续单元，与内容无关 |
| 先验与适用 | 需要分隔符能对应到单元边界；依赖分词器与语言 | 不需要 |

## 3. 什么情况下分隔符分块会失效（论证）

1. **非句子单元**：vt 的赋值链是 `VAR X = VAR Y`，单元之间没有句号，几个赋值可能落在同一“句子”里，也可能被换行切开；
   UUID 值（niah_single_3、multikey_3）的单元有 24–75 个 token，超过块长上限时必然被截断，退化为固定网格。
2. **长句截断**：句子超过块长上限时，按 B 截断就重新引入了固定网格的切分问题，而且没有第二套网格来补救。
3. **合并稀释**：短句向后合并后，单元与无关句子共享一个块，矩摘要的单元占比 f 下降（THEORY §3 F2）。这正是 G 产生的机制之一，只是从“被切开”换成了“被稀释”。
4. **分隔符先验**：数字串、代码、表格、无标点文本中，分隔符与单元边界不对应。TWIN-GRID 的保证不依赖这一点。

## 4. 它在什么情况下可能更好（如实写明）

- 单元恰好是一个句子，而且句长 ≤ 块长上限时（RULER 的 niah 数字 needle 正是这种情况），分隔符分块能把单元完整放进**一个**块，摘要量还可能少于 2×。
  此时它与 TWIN-GRID 的差别主要在装箱效率和变长摘要的可比性（log 块长修正），没有先验理由认为 TWIN-GRID 一定更好。
- 所以这个对照的意义在于：说明 TWIN-GRID 的优势是**与内容无关的保证**，而不是在 needle 句子上一定胜出。

## 5. 开发对照（计划；探索性质）

- 数据：P-grid 那批 7 个有单元的任务 × 20 条（Qwen2.5-1.5B，16k，读取预算 512）。
- 方法 delim_cobs（src/delim_attn.py，运行时替换打分入口，不改冻结的 sparse_attn.py）：
  - 候选区 [U, fe) 按句末 token 切块；过长的按 B 截断；过短的向后合并到不超过 B；
  - 打分 = log(块长) + 均值 + ½·投影方差（与 cobs 同一摘要）；
  - 排序目标是**估计的块对数质量**（含 log 块长），不是每 token 的质量密度；这是在看结果之前规定的唯一排序，之后不换；
  - 按分数从高到低整块装入，直到下一块装不下；用这一块的前缀补满严格预算（读取 token 数与其它方法相同，sparse_attn 的逐次预算断言照常生效）；
    每次调用记录补满 token 数，报告补满占预算的比例（均值、最大值）；
  - 句末判定：解码后 token 文本含 {. ? ! \n} 中的字符；小数点、缩写等造成的过度切分由“过短向后合并”吸收；
  - 布局：sink、local、常驻区与候选区与 cobs 相同（U = 32）；摘要量 = 候选区块数 ÷ 候选 token 数，与单网格 1/32、TWIN-GRID 2/32 放在同一张表；
- 对照臂：cobs、cobs+g2f（复用 P-grid 的输出）。
- **三者都不是等内存（审查方批次 6，Z1）**：每候选 token 的摘要数，单网格 1/32 ≈ 0.031，TWIN-GRID 2/32 ≈ 0.063，delim 随句子数变化
  （合成检查中约 0.041，实际值由运行报告）。所以 delim − (cobs+g2f) 只能解读为“内容相关划分 vs 内容无关双网格”两种设计的比较，不是等内存比较。
- 生成段（Z2）：句末只从 prompt 算出，生成的 token 按 B 截断；这 7 个任务的生成都很短，影响可以忽略；以后用于长生成任务时须另行处理并写明。
- 报告（src/delim_dev_analysis.py）：按单元的 32 网格类别（in0 / repair / out）与“delim 覆盖”（单元完整落在一个 delim 块内）分别给出准确率、
  单元数和以样本为单位的区间；逐任务比较 TWIN-GRID 覆盖率与 delim 覆盖率（预期 delim 在 vt 上覆盖较差）；另报告用 cobs 重跑检验运行器保真度
  （与 P-grid 的 cobs 输出逐条相同）。只作描述，不进入任何检验。
- 分析脚本与运行器在运行启动前提交（审查方批次 5）；集群上至多作为“v1.4 附录（描述性），不改检验定义”，由独立的生成脚本给出作业。

# 附录 A2：读邻块的简单替代方案与几何覆盖的对偶（2026-10-16；用户第二轮评价、审查方批次 7）

## 6.1 定位：重叠滑动块
TWIN-GRID 本身就是步长 B/2、重叠约 50% 的滑动块，另加去重和精确预算填充（g2_fill_v1），所以它不是重叠滑动块的替代方案，而是其中一种。
更有意义的问题是重叠比例与摘要内存之间的权衡：k 套网格时覆盖上界为 (k−1)B/k + 1（L1），摘要内存为 k×。
重叠压缩本身并不新（NSA 压缩分支采用重叠块；引用以 reports/ 中核对过原文的条目为准）。k = 3 的探索不在当前计划内。

## 6.2 引理 L1′（几何覆盖的内存–读取对偶；已证，theory/check_nbh.py 穷举）
单网格块 [b₀, b₀+B)，h = B/2。任一长度 ℓ ≤ h+1、与该块相交的连续段，都完整落在窗口 [b₀−h, b₀+B+h) 内；ℓ = h+2 时不一定成立。
证明：相交意味着起点 x ≥ b₀−(ℓ−1) ≥ b₀−h，终点 x+ℓ−1 ≤ b₀+B−1+(ℓ−1) ≤ b₀+B−1+h。∎
对偶关系：
- **TWIN-GRID** 用 2× 的摘要内存换覆盖，每个种子的读取不变（B）；
- **两侧各扩半块（cobs+nbh）** 不需要额外的摘要内存，每个种子的读取最多为 2B，所以固定读取预算下种子数约减半。
两者都在 ℓ ≤ h+1 时保证覆盖，代价分别落在内存和读取上。

## 6.3 预测（开发运行，src/variants_dev_analysis.py 在运行前提交）
- nbh：在单单元任务（niah_single_1/2、niah_multikey_1/2）上接近 cobs+g2f；在多单元任务（niah_multivalue、niah_multiquery、vt）上应当吃亏，因为种子数减半。
- +nb（两侧取分高的整块）、+nbr（只向右）：每个种子读 2B，种子数减半。+nbr 依赖“key 在前、value 在后”的内容顺序，它针对的正是 E5 中“value 末尾被切到右侧”的难例，所以是最强的简单替代方案。
- 早期开发数据（results/nb_16k.md，旧协议，60 题）中 quest+nb 下降 16.3 个百分点：代码核对显示 _dilate 恰好选 k 个块，没有发现计数错误；最可能的原因是种子块减半伤了多 needle 任务（multivalue 从 0.46 降到 0.28）。旧协议无法复核，当前计划不重跑 quest+nb。

## 7.2 谁需要 TWIN-GRID
原文核对（reports/related_work_verified_ZH.md）：MoBA 用一阶均值池化打分，但块长为 512–4096、不重叠；InfLLM 用每单元 4 个代表 token（不是均值）；
NSA 压缩分支 l = 32、d = 16，正是两套错开半块的网格（以“防止碎片化”为目的，φ 端到端训练）。
因此：(i) 错位半块网格的布局本身已有先例，贡献须收窄到免训练选择中的误差源刻画、覆盖保证（L1）、预算不增加与增益律；
(ii) 增益律预测切分只在小块时重要：跨界概率 π ≈ (ℓ−1)/B，块长 4096 时 ℓ ≈ 12 的单元只有约 0.3%，所以 MoBA 原生设定下 TWIN-GRID 的预期增益接近 0；
需要它的是块长为数十 token 的免训练选择（Quest 类页面、NSA 类小选择块）。
在小块下，增益律预测一阶均值摘要的跨界惩罚 G 最大（F 模型中的 fΔ 项），即 G_mean ≥ G_cobs > G_quest。
开发对照：mean、mean+g2f、quest（B32）。预测 G 的顺序，并单列 mean+g2f vs quest 的等内存比较（不预设方向）。
如果对 quest32 与 quest16 的两种比较都不成立，叙述的重心应转向“边界切断是块稀疏注意力的一个独立误差源，G 是它的度量”，而不是“TWIN-GRID 让矩摘要追平 Quest”。

## 7.3 推论（块长依赖；审查方批次 8）
**上界（对任何摘要类型成立）**：段内项以外的增益 = π·(a′_rep − a_rep) ≤ π，因为 a′_rep ≤ 1、a_rep ≥ 0；均匀起点下 π ≈ (ℓ−1)/B（用 tokenizer 测得的精确 π 时就是 π 本身）。
所以**段内项以外的增益以 (ℓ−1)/B 为上界，块长增大时必然趋于 0**；这不依赖 G 的形状。G 本身会随 B 变化（F 模型中单元占比 f = m/B 随 B 改变），
所以不能推出“Δ/π̂ 在不同块长下为常数”（批次 8 更正）。
因此 TWIN-GRID 只对块长为数十 token 的免训练选择方法有意义；MoBA 的块长 512–4096 时 π ≈ 0.3%，增益上界约 0.3 分。
可检验形式：在每个块长 B 下分别检验 Δ ≈ π̂(B)·Ĝ(B)。这一检验不在 v1.4 计划内（主格只有 B = 32，层 2 有 B = 16 的描述臂），如要做须另立条目。
（撤回：批次 7 曾把 MoBA 列为“需要 TWIN-GRID 的系统”，按原文块长已撤回；mean 打分器保留，只用于检验“一阶摘要的 G 最大”和等内存对照。）

## 8.2 块长三效应（解释；审查方 E2）
块长 B 同时控制三种效应：
（只有第 1 种已直接度量；第 2、3 种是解释开发结果的假设，由 §8.2 末的 box 摘要 P-grid 区分。）
1. **切分**：单元跨界概率 π ∝ 1/B —— 块越小越不利；
2. **单元占比**：f = m/B ∝ 1/B —— 块越小，单元在块内的占比越大，矩摘要越容易把它排上来（F 模型）；
3. **可选位置数**：固定读取预算下可选的块数 ∝ 1/B —— 块越小，多目标任务越容易同时选中各个目标。
TWIN-GRID 用 2× 摘要内存**只消除第 1 种**；等内存的 B/2 单网格得到第 2、3 种，同时承受翻倍的切分。本机开发数据显示后者占优。
增益律（THEORY §4）只刻画第 1 种效应：它的适用范围应限定为“**固定 B 下加不加 TWIN-GRID**”，不能用来比较不同块长的设计。
区分第 2、3 种的对照（审查方 E4，运行前提交分析）：box 摘要对 f 不敏感，所以 quest16 vs quest32+g2f 在四目标任务上若仍明显差距，就是第 3 种效应。

## 8.3 对理论命题的结论
- **L3**（细网格的可达集合包含错位网格的可达集合）：开发结果与之一致——L3 允许细网格更好，但并不预测细网格更好（审查方批次 10 复核更正措辞）。
- **L4**（单次选择 vs 联合选择）：条件命题本身无误，但其前提（碎片的入选概率低于整块）在这些数据上不成立；P-grid 记为“预测未满足”。
  审查方撤回批次 1 T2 依据单单元玩具模拟提出的“F、R 都预测 twin ≥ fine”（玩具忽略了效应 2、3）。
- **TWIN-GRID 剩余可能的适用场景**：读取或 kernel 粒度被固定为 B（不能改用更小的块）时。这一点未经检验，只是假设。
