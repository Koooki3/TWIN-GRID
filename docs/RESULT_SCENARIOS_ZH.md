## 0. 读数

| 读数 | 来源 | 定义 |
|---|---|---|
| D̄ | cluster/aggregate.py | 主比较 cobs+g2f − cobs 的 13 任务宏平均得分差（分），分层符号翻转 p，分层 bootstrap 95% 区间 |
| Holm 两项 | cluster/holm.py | nf_pt1±g2f；可覆盖子集上的 cobs±g2f。按 Holm 决策逐项报告，不合并 |
| Δ̂ | cluster/gain_law.py | 预测增益，**13 任务宏平均**：有单元任务为 100·π̂_t·Ĝ_cf,t，无单元任务（cwe、fwe、qa_1、qa_2）按 π = 0 计入，与 D̄ 同分母 |
| κ | cluster/gain_law.py | 合计校准比（cobs、nf_pt1、quest32 各格合计，交叉拟合），95% 区间 |
| Ĝ、R̂_repair、R̂_out | cluster/gain_law.py | cobs 的跨界惩罚与修复比，95% 区间（以样本为单位的任务内 bootstrap） |
| MDE | 计划 §3.5 | 主比较功效 0.8 时的最小可检出效应 ≈ 1.7 分 |
| Q | 描述性臂 | quest32 的宏平均是否 ≥ cobs+g2f |

派生判定：
- **主比较**：显著 = p < 0.05 且 D̄ > 0；弱阳性 = D̄ > 0 且 p ≥ 0.05；阴性 = D̄ ≤ 0。
- **κ**：相符 = 区间含 1 且不含 0.5；不成立 = 区间不含 1；其余为不确定。
- **切分惩罚**：未检出 = Ĝ 区间含 0；存在 = Ĝ 区间下限 > 0。
- **修复**：未修复 = R̂_repair 区间含 0；已修复 = R̂_repair 区间下限 > 0。

## 2. 情景叙述

**S1（显著，增益与增益律相符，Quest 不占优）**：
“在官方 RULER 上、冻结的 8B 模型中，TWIN-GRID 在相同读取预算下提高了矩摘要打分器的官方得分（D̄ = …，p = …）；增益大小与运行前由 tokenizer 给出的 π̂ 和基线臂 Ĝ 的预测相符（Δ̂ = …，κ = …）。”只主张矩类摘要；不作速度主张。

**S1′（显著，但大小不符或无法判定）**：报告效应与 κ 区间；不把增益律作为解释；“增益存在，但其大小不能由 π̂·Ĝ 预测（该格 κ = …）”。
- κ 区间整体 < 1：“增益小于增益律的预测：切分惩罚只被部分修复（R̂_repair = …）或被段内项抵消”；
- κ 区间整体 > 1：“增益大于增益律的预测：除修复切分外还有别的来源（例如 in0 单元上的变化或摘要冗余），增益律低估了它”，并报告段内项与 R̂_out；
- κ 不确定：只报告区间。

**S2a（弱阳性，预测增益本就小于 MDE）**：
“8B 模型在被切开单元上的本底失败较少（Ĝ = …），增益按增益律等比例缩小（Δ̂ = … < MDE，D̄ = …），主比较未达显著。这在冻结计划的功效分析中已预先写明（g ≈ 0.10 时功效约 0.36）。不追加样本。”

**S2b（弱阳性，κ 不成立）**：
- κ 区间整体 < 1：“增益律在该格不成立：被切开单元的惩罚 Ĝ 存在，但双网格没有按预期修复（R̂_repair = …）”，再按 R̂_out 与单元类别分布讨论原因；
- κ 区间整体 > 1：“实测增益大于预测，但主比较未达显著：增益律低估了增益”，报告段内项与 R̂_out，不作“修复不足”的叙述。

**S2c（不确定：方向一致但精度不足）**：只报告 D̄、Δ̂、κ 的估计与区间，写“方向与预测一致，但精度不足以判断”，不作“等比例缩小”或“不成立”的结论。

**S3（阴性）**：“在 8B、官方 RULER 上未观察到 TWIN-GRID 的增益（D̄ = …）。”
- **S3a 切分惩罚未检出**（Ĝ 区间含 0）：本机 1.5B 上的切分惩罚在 8B 上未检出，TWIN-GRID 的适用前提不成立；本机结论只限于 1.5B。
- **S3b 有惩罚但未修复**（Ĝ 下限 > 0 且 R̂_repair 区间含 0）：双网格没有修复切分，与本机 R ≈ 0.92 不一致，如实报告为相互矛盾的结果。
- **S3c 其余阴性**：有惩罚且已修复但总增益 ≤ 0 时，修复收益被段内项（候选数翻倍带来的干扰稀释）或 out 类单元抵消，按段内项与 R̂_out 如实报告；Ĝ 整体 < 0（切开反而更好）时如实报告为与本机方向相反。

**S4（增益与增益律相符，但 Quest 仍最好；按本机数据最可能出现）**：
- “TWIN-GRID 修复了矩类摘要的边界切断（增益与增益律相符），但 box 摘要（Quest）对切分本就不敏感（Ĝ_quest = …），所以在该设定下仍是最佳单一打分器。”
- 贡献按 README 的四条叙述，重心是“边界切断是免训练块选择的独立误差源，G 按摘要类型度量”。
- 等内存比较只作描述并如实列出：mean+g2f vs quest32（同为每 token 8 个 float）；cobs+g2f vs quest16（0.64× 内存）。若两者都不利于矩类摘要，不主张“矩摘要 + TWIN-GRID 优于 Quest”。
